看到了你的线上版本，页面框架和交互元素都已完整展现，但控制台报了一个关键错误，导致 3D 地球核心无法渲染。在讨论未来规划之前，我们必须先解决这个阻塞性问题。

🚨 线上问题诊断

你的页面报错 Error constructing CesiumWidget.，并提示 visit http://get.webgl.org to verify that your web browser and hardware support WebGL。这意味着 Cesium.js 初始化失败了。

这通常不是你的代码逻辑问题，而是运行环境或资源加载问题。针对 popmap.html 和 app.js 的协同工作方式，最可能的原因是：

WebGL 上下文丢失：你的浏览器或显卡驱动确实不支持 WebGL，或者因为其他程序占用过多 GPU 内存导致 WebGL 创建失败。你可以在浏览器中访问 http://get.webgl.org 来确认，正常应该看到一个旋转的立方体。

静态资源加载失败：popmap.html 和 app.js 中引用的 Cesium 静态资源（如 Workers, Assets, Widgets）路径不正确或加载失败。这是将 Cesium 从 CDN 改为本地部署时最容易出现的问题。检查 popmap.html 顶部的 window.CESIUM_BASE_URL 设置，确保路径正确且文件可访问。

关键 API Key 失效：Cesium Ion Token 失效或权限不足，导致必须的全球地形或影像服务无法加载，也可能引起初始化错误。检查 Cesium.Ion.defaultAccessToken 是否有效。

初始化代码执行顺序错误：在 app.js 中，const viewer = new Cesium.Viewer(...) 这行代码执行时，popmap.html 中的 <div id="cesiumContainer"> 还没有完全准备好。

🔧 紧急修复方案

请按以下顺序排查，大部分情况能立刻解决：

1. 快速自检（30秒）
   检查 WebGL：在电脑的 Chrome/Edge 浏览器中访问 http://get.webgl.org。如果不能显示立方体，请更新显卡驱动或切换浏览器。
   重新生成 Cesium Token：登录 Cesium ion，创建一个新的默认 Access Token，并替换 popmap.html 中 Cesium.Ion.defaultAccessToken 的值。这是最简单的尝试。

2. 检查静态资源路径（如果是本地化部署）
   如果你是将 Cesium 库下载到了 cesium/ 文件夹，请确保 popmap.html 顶部有如下设置，并且文件夹结构完全对应：
   window.CESIUM_BASE_URL = './cesium/';
   同时，确认 cesium/ 文件夹内包含了 Assets, Workers, Widgets, ThirdParty 和 Cesium.js 等核心文件。

3. 检查代码执行顺序
   确保 app.js 在 popmap.html 的 <body> 末尾加载，这样当它执行 new Cesium.Viewer('cesiumContainer') 时，DOM 容器一定已经存在。

4. 检查筛选按钮的 JS 绑定
   在你同步的 app.js 内容中，有一段为不存在的 filter-sight 等元素绑定事件的代码。这不会导致 WebGL 错误，但会报 TypeError，需要清理。
